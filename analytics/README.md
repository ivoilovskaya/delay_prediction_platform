# Аналитика участков: первая версия

Процесс `analytics.worker` читает телеметрию и вручную заданные маршруты из входной базы (`DATABASE_URL`). В неё он ничего не записывает. Административная команда `analytics.routes` один раз создаёт там таблицы `routes`, `route_stops`, `route_segments`, `vehicle_route_assignments` и добавляет маршрут. Результаты расчёта находятся только в `RESULTS_DATABASE_URL`: `vehicle_state`, `segment_passages`, `segment_baseline`, `segment_state`, `alerts`.

Для SQLite сначала создайте две базы штатными командами:

```sh
python -m ndtp_ingestion.db_init
python -m ml.results_db
python -m analytics.results
```

Скопируйте [шаблон](examples/route.template.json), замените примерные остановки реальными координатами и стабильными ID. В `assignments` укажите `tr_id` **автобуса**, направление и интервал назначения (`valid_from`, `valid_to`, ISO 8601 с UTC-смещением). Например:

```json
{"tr_id": 42, "direction_id": "outbound", "valid_from": "2026-09-27T09:00:00+00:00", "valid_to": "2026-09-27T10:00:00+00:00"}
```

Затем импортируйте маршрут и запустите процесс:

```sh
python -m analytics.routes --file /absolute/path/to/route.json
python -m analytics.worker
```

Для исторического проигрывания запускайте `python -m analytics.worker --once --at 2026-09-27T09:05:00+00:00` с **возрастающими** моментами времени. В каждом цикле используются только GPS-пакеты с временем события и временем приёма не позже этого момента. Повторный запуск того же момента не создаёт второе прохождение.

API диспетчера: `GET /analytics/segments` и `GET /analytics/alerts`. На странице `/` они показываются в блоке «Где движение замедляется» и на карте. При отсутствии маршрута интерфейс показывает пустое состояние, без придуманного риска.

## Как считается

- Привязка к участку требует явного назначения автобуса и трёх последовательных достоверных GPS-точек рядом с линией между остановками. Неоднозначное положение отмечается `UNKNOWN`.
- Время завершённого прохождения считается по времени событий GPS. До трёх качественных прохождений норма берётся из вручную указанного планового времени и отмечается как `planned`; затем используется медиана истории.
- Для автобуса в пути ранняя оценка равна прошедшему времени плюс оставшаяся доля участка, умноженная на норму. Время «сейчас» — медиана ранних оценок и недавних завершённых прохождений от разных автобусов.
- `WATCH` возможен при одном замедлившемся автобусе. `WARNING` требует как минимум двух подтверждений, достаточной уверенности и сохранения сигнала в двух циклах. Индекс риска `0–100` отражает тяжесть и согласованность наблюдений; это **не вероятность**.
- Средняя скорость — медиана GPS-скоростей за активные и недавние прохождения. Участки разных направлений считаются раздельно. Линии на карте схематичные и не повторяют геометрию дорог.

Текущая версия **не** определяет причины задержки, не рассчитывает интервалы между автобусами и не связывает ML-прогноз конкретной остановки с участком. Для боевой проверки нужны настоящие стабильные ID остановок, назначения ТС по времени и геометрия маршрутов. Случайный маршрут эмулятора для такой проверки не подходит.


## Docker и сроки хранения

В живом Compose аналитика работает в отдельном сервисе `analytics`. Подготовка
`prepare` создаёт её таблицы до старта. Для импорта своего JSON в том же проекте:

```sh
docker compose run --rm --no-deps --volume /absolute/path/route.json:/route.json:ro analytics python -m analytics.routes --file /route.json
```

Результаты очищает отдельный сервис `results-maintenance`, командой
`python -m maintenance.results`, без зависимости от ML или analytics worker.
По умолчанию `vehicle_state` и `segment_state` хранятся сутки,
`segment_passages` и `segment_baseline` — 30 суток, `alerts` — 7 суток.
Обновляемые нормы/предупреждения сохраняются по времени последнего обновления.
Для каждой таблицы настраиваются `<ИМЯ_ТАБЛИЦЫ>_RETENTION_S` и
`<ИМЯ_ТАБЛИЦЫ>_CLEANUP_INTERVAL_S` (имя прописными буквами); общий интервал —
`RESULTS_CLEANUP_INTERVAL_S=600`. Подробные правила — в корневом README.
В `DATA_TIME_MODE=stream` обслуживание выключено. Прежняя настройка
`ML_TIME_MODE` используется, если `DATA_TIME_MODE` не задана.
