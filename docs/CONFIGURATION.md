# Настройки и переменные проекта

Краткая справка по значениям, которые можно менять без правок Python-кода.
Актуальный пример для Docker находится в [`.env.example`](../.env.example).

## Настройки диспетчера

| Что меняется | Как | По умолчанию |
|---|---|---|
| Порог красного/жёлтого сигнала | Поле «Порог опоздания» на странице | 5 минут; варианты 2, 5, 10 минут |
| Область автобусов | Фильтр «Зона ответственности» | Все ТС; доступна также восточная и южная зона |
| Остановки и схематичная маршрутная сеть | Переключатель слоя «Остановки» | Включён |

Порог действует для текущей оценки задержки и свежего прогноза. Он хранится в
состоянии страницы и сбрасывается при её перезагрузке. Это порог отображения,
он не меняет расчёты модели.

## Режим, цикл и свежесть

| Переменная | Назначение | Значение по умолчанию |
|---|---|---:|
| `DATA_TIME_MODE` | `wall` — текущее время, `stream` — время последней записи/воспроизведения | Docker live: `wall`; Docker historical: `stream` |
| `ML_INTERVAL_S` | Пауза между циклами live ML-воркера | Docker: 10 секунд; отдельный worker: 30 секунд |
| `ML_WINDOW_S` | Окно телеметрии для ML | 2700 секунд (45 минут) |
| `PREDICTION_MAX_AGE_SECONDS` | Возраст, после которого прогноз считается устаревшим | 90 секунд |
| `MODEL_TYPE` | Модель: `ensemble`, `boosting`, `catboost`, `torch`, `baseline` | `ensemble` |
| `PORT` | Локальный порт backend | 8000 |

Historical Compose переигрывает время шагами: `REPLAY_STEP_S` (10 секунд
исторического времени за шаг) и `REPLAY_TICK_S` (пауза между шагами, 1 секунда).
Это не интервал ML-воркера. В режиме `stream` очистка исторических результатов
выключена.

## Сроки хранения и очистка

Все интервалы и сроки хранения задаются в **секундах**. По умолчанию данные
очищаются каждые 600 секунд (10 минут); отдельная таблица может иметь свой
интервал очистки.

| Переменная | Данные | По умолчанию |
|---|---|---:|
| `TELEMETRY_RETENTION_S` | Входная GPS-телеметрия | 7200 секунд (2 часа) |
| `SCHEDULE_RETENTION_S` | Прошедшие точки расписания; будущий план сохраняется | 21600 секунд (6 часов) |
| `PREDICTIONS_RETENTION_S` | Прогнозы в БД результатов | 86400 секунд (24 часа) |
| `VEHICLE_STATE_RETENTION_S` | История состояния ТС | 86400 секунд (24 часа) |
| `SEGMENT_PASSAGES_RETENTION_S` | Завершённые прохождения участков | 2592000 секунд (30 дней) |
| `SEGMENT_BASELINE_RETENTION_S` | Нормативное время участков | 2592000 секунд (30 дней) |
| `SEGMENT_STATE_RETENTION_S` | Сводные состояния участков | 86400 секунд (24 часа) |
| `ALERTS_RETENTION_S` | Предупреждения по участкам | 604800 секунд (7 дней) |
| `CLEANUP_INTERVAL_S` | Очистка входной БД | 600 секунд (10 минут) |
| `RESULTS_CLEANUP_INTERVAL_S` | Общий интервал очистки БД результатов | 600 секунд (10 минут) |

Для независимого расписания можно задать, например,
`PREDICTIONS_CLEANUP_INTERVAL_S=300` или
`SEGMENT_PASSAGES_CLEANUP_INTERVAL_S=3600`. Для остальных таблиц действует
общий `RESULTS_CLEANUP_INTERVAL_S`.

Проверки конфигурации требуют, чтобы `TELEMETRY_RETENTION_S` было не меньше
`ML_WINDOW_S + 60`, а `SCHEDULE_RETENTION_S` — не меньше 21600 секунд.
При настройке срока хранения телеметрии изменяйте окно ML и срок хранения
согласованно. Очистка БД результатов не работает в historical-режиме.

## Аналитика участков

Эти значения меняют правила сопоставления GPS с вручную заданной сетью и
порог подтверждения замедления. На диспетчерские цвета «сейчас/прогноз» они
не влияют.

| Переменная | Назначение | По умолчанию |
|---|---|---:|
| `ANALYTICS_INTERVAL_S` | Частота цикла аналитики | 30 секунд |
| `ANALYTICS_CORRIDOR_M` | Максимальное расстояние GPS-точки от участка | 150 м |
| `ANALYTICS_ACTIVE_S` | Как долго ТС считается активным на участке | 120 секунд |
| `ANALYTICS_RECENT_S` | Окно недавних прохождений | 600 секунд |
| `ANALYTICS_SLOWDOWN_RATIO` | Во сколько раз дольше нормы — считать замедлением | 1.4 |
| `ANALYTICS_MIN_BASELINE_N` | Прохождения до замены плановой нормы исторической | 3 |
| `ANALYTICS_MIN_CONFIRMING` | Минимум ТС для подтверждённого предупреждения | 2 |

## Где задать значения

Для Docker Compose скопируйте пример в `.env` рядом с `compose.yaml`, измените
нужные строки и пересоздайте соответствующие сервисы:

```bash
cp .env.example .env
# отредактируйте .env
# применить все настройки

docker compose up -d --build
```

Изменение `PORT` влияет только на опубликованный порт backend. Большинство
переменных Compose передаёт нужным сервисам; исторический запуск читает
`REPLAY_STEP_S` и `REPLAY_TICK_S`. Перед изменением окружения historical Compose
проверьте его отдельным файлом.

При локальном запуске Python `.env` автоматически не загружается. Задайте
переменные окружения в терминале перед запуском. Например:

```bash
export PREDICTION_MAX_AGE_SECONDS=120
export ML_INTERVAL_S=15
python -m ml.worker
```

Некоторые технические параметры подключения, например `DATABASE_URL`,
`RESULTS_DATABASE_URL`, адрес NDTP и ID-таблиц, тоже настраиваются.
Они перечислены в [`.env.example`](../.env.example); обычно их меняют только
при подключении другого источника данных или переносе сервиса.
